# Per-object robot-base tracking

Implement tracker.py as a separate, attach-only process. Input is detection_shm;
output is tracking_shm, owned exclusively by main.py/ProductIpc. Never send robot
commands or write target_shm. Unknown object speeds remain adjustable, not assumed
calibrated. Defaults: 0.10 m matching gate, 0.30 s maximum missed/stale age,
3 consecutive hits to confirm, position noise 0.005 m, acceleration noise 1 m/s².

1. Write synthetic tests: reversed detection ordering, constant speed, variable dt,
   one-to-one gated Hungarian assignment, empty/missed/reacquired objects,
   confirmation/expiry, timestamp rejection, bounded 8-track capacity, servo-time
   extrapolation and stale-input refusal.
2. Implement 6-state constant-velocity Kalman filters with per-object monotonic IDs,
   Joseph covariance update and gated Hungarian matching including unmatched slots.
   Retain most recent observed rotation; expose full 6x6 state covariance.
3. Reuse DetectionShm locking/lifecycle with class-level NumPy layouts; derive
   TrackingShm carrying track_id, confirmed/observed, last_seen, velocity and covariance.
4. Poll new capture timestamps once each; clear output on invalid/stale input and
   shutdown. Consumers extrapolate to their target PC time; no claim of Python
   hard-real-time 500 Hz execution. Expose all tuning values via CLI.
5. Add tracking SHM to ProductIpc creation, stale cleanup, shutdown and tests.
   Add a compact tracker table below existing main.py sections, preserving summary.
6. Verify synthetic trajectory accuracy, independent SHM attachment, CLI help,
   relevant existing tests and document execution/consumer timestamp semantics.
